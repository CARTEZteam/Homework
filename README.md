Арена новичка: от первого запуска до трёх раундов

Консольная программа на Java, которая регистрирует героя, проверяет возможность допуска на арену и запускает три последовательных боя с противниками.

1. Описание проекта

Проект выполнен в рамках практической работы «Среда разработки и основы языка Java».

Программа демонстрирует основные конструкции языка Java:

переменные и типы данных;
условные конструкции `if / else`;
логические операторы `&&` и `||`;
циклы `for` и `while`;
массивы;
конструкцию `switch`;
методы с параметрами и возвращаемым значением;
работу со `String`;
обработку пользовательского ввода через `Scanner`;
компиляцию `.java` в `.class`;
запуск программы через JVM.

4. Выбранный вариант

Использован вариант А — Руины.

В программе используются три противника:

| Раунд | Противник | HP | Урон |
| ----- | --------- | -: | ---: |
| 1     | Крыса     | 12 |    4 |
| 2     | Скелет    | 18 |    6 |
| 3     | Страж     | 24 |    8 |

Сила атаки героя:
10

Начальные характеристики героя:
HP = 40
XP = 0

За победу над каждым противником герой получает:
20 XP

5. Правила допуска на арену

Для участия герой должен соответствовать условию:
level >= 10 && (hasShield || heroClass.equals("маг"))

Это означает:

уровень должен быть не меньше 10;
дополнительно герой должен иметь щит или иметь класс `маг`.

Например:
Воин, уровень 10, щит: да → допущен
Воин, уровень 10, щит: нет → отказ
Маг, уровень 10, щит: нет → допущен
Воин, уровень 9, щит: да → отказ

6. Регистрация героя

При запуске программа запрашивает:

1. Имя героя;
2. Класс;
3. Уровень;
4. Наличие щита.

Допустимые классы:
воин
маг
лучник

Имя должно содержать от 1 до 30 символов.

Уровень должен находиться в диапазоне от 1 до 80.

Для строк используется очистка пробелов и приведение к нижнему регистру.

7. Игровой процесс

После успешного допуска начинаются три раунда.

В каждом бою доступны команды:
1 — атаковать
2 — лечиться
0 — закончить игру

Атака:

Герой наносит противнику 10 единиц урона.

Если противник выживает, он наносит ответный удар.

Если последняя атака уничтожает противника, ответного удара нет.

Лечение:

Лечение восстанавливает 8 HP, но максимальное здоровье героя не может превышать 40 HP.

Лечение можно использовать только один раз за бой.

Повторная попытка лечения не изменяет состояние героя и не передаёт ход противнику.

Завершение игры
Команда `0` немедленно завершает игру и выводит результат:

Игра прервана

Если HP героя становится равным 0, герой проигрывает.

Если герой побеждает всех трёх противников, выводится:

Арена пройдена

8. Использованные массивы

Противники хранятся в трёх связанных массивах:
String[] enemyNames = {"Крыса", "Скелет", "Страж"};
int[] enemyHp = {12, 18, 24};
int[] enemyDamage = {4, 6, 8};

Одинаковый индекс обозначает одного противника.

Например:
enemyNames[0]  → Крыса
enemyHp[0]     → 12
enemyDamage[0] → 4

Массивы имеют фиксированный размер 3, поэтому программа выполняет ровно три раунда.

9. Основные методы

В программе выделены отдельные методы для разных задач.

Проверка допуска
static boolean isAllowed(int level, boolean hasShield, String heroClass)

Возвращает `true`, если герой соответствует условиям допуска.

Расчёт HP после урона

static int calculateDamageHp(int currentHp, int damage)

Уменьшает HP и не позволяет получить значение меньше 0.

Расчёт HP после лечения
static int calculateHealHp(int currentHp)

Увеличивает HP на 8, но не позволяет превысить максимальное значение 40.

Вывод итогового результата

static void printResult(...)

Выводит имя героя, выбранный вариант, количество побед, XP, оставшееся HP и итог игры.

10. Компиляция и запуск

Перед запуском необходимо проверить установленную версию Java:
java --version

Проверить компилятор:
javac --version

Обе команды должны показывать версию 21.

Компиляция

Из корневой папки проекта:
javac -encoding UTF-8 -d out src/Main.java

Запуск
java -cp out Main

11. Как работает компиляция

Исходный файл:
Main.java

компилируется с помощью:
javac

и превращается в:
Main.class

После этого JVM запускает скомпилированный класс командой:
java -cp out Main

Схема работы:
Main.java
    ↓
javac
    ↓
Main.class
    ↓
JVM
    ↓
запуск программы

IntelliJ IDEA автоматически выполняет эти действия при запуске проекта.

12. Контрольная проверка

Проверка А — прохождение всех трёх раундов

Ввод:
Имя: Артур
Класс: ВОИН
Уровень: 10
Щит: да

В каждом бою используется только команда:
1

Ожидаемый результат:
Раунд 1: победа, HP героя 36, XP 20
Раунд 2: победа, HP героя 30, XP 40
Раунд 3: победа, HP героя 14, XP 60

Итог:
Побед: 3
XP: 60
HP: 14
Итог: Арена пройдена

Проверка Б — маг без щита

Ввод:
Имя: Мерлин
Класс: маг
Уровень: 10
Щит: нет

Герой должен быть допущен к арене.

Причина: условие допуска разрешает участие магу без щита при уровне от 10.

Проверка В — недостаточный уровень

Ввод:
Имя: Артур
Класс: воин
Уровень: 9
Щит: да

Ожидается:
Отказ: недостаточный уровень.

Бои не начинаются.

Проверка Г — отсутствие защиты

Ввод:
Имя: Артур
Класс: воин
Уровень: 10
Щит: нет

Ожидается:
Отказ: нужна защита — щит или класс маг.

Бои не начинаются.

Проверка Д — ограничение лечения

Если герой использует лечение дважды в одном бою, вторая попытка не изменяет состояние:
Лечение уже использовано в этом бою.

Противник также не получает дополнительный ход.

Проверка Е — неизвестная команда

При вводе команды, отличной от `0`, `1` и `2`:

Неизвестная команда. Введите 1, 2 или 0.

Состояние героя, противника, XP и доступность лечения не изменяются.

13. Известные ограничения

Программа является учебной консольной версией арены.

Ограничения:

используется только один игровой вариант — А «Руины»;
урон противников фиксированный;
случайность не используется;
данные героя не сохраняются после завершения программы;
графический интерфейс отсутствует;
все игровые данные находятся непосредственно в исходном коде.

Фиксированный урон используется специально, чтобы контрольные сценарии давали одинаковый результат при каждом запуске.
